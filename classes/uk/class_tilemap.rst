TileMap
=======

**Застаріло:** Use multiple :ref:`TileMapLayer<class_TileMapLayer>` nodes instead. To convert a TileMap to a set of TileMapLayer nodes, open the TileMap bottom panel with the node selected, click the toolbox icon in the toolbar and choose 'Extract TileMap layers as individual TileMapLayer nodes'.

**Успадковує:** :ref:`Node2D<class_Node2D>` **<** :ref:`CanvasItem<class_CanvasItem>` **<** :ref:`Node<class_Node>` **<** :ref:`Object<class_Object>`

Node для 2D кахельних карт.

.. rst-class:: classref-introduction-group

Опис
--------

Вузол для 2D карт на основі плиток. Карти плиток використовують :ref:`TileSet<class_TileSet>`, який містить список плиток, які використовуються для створення карт на основі сітки. TileMap може мати кілька шарів, які розміщують плитки одна над одною. 

З міркувань продуктивності всі оновлення TileMap групуються в кінці кадру. Примітно, що це означає, що фрагменти сцени з :ref:`TileSetScenesCollectionSource<class_TileSetScenesCollectionSource>` можуть бути ініціалізовані після батьківського елемента. Це додається до черги лише всередині дерева сцени.

Щоб примусово виконати оновлення раніше, викличте :ref:`update_internals()<class_TileMap_method_update_internals>`. 

\ **Примітка:** З міркувань продуктивності та сумісності координати, серіалізовані за допомогою **TileMap**, обмежені 16-бітними цілими числами зі знаком, тобто діапазон координат X і Y становить від ``-32768`` до ``32767``. Під час збереження даних плитки за межами цього діапазону обгортаються.

Якщо увімкнено, TileMap побачить свої зіткнення, що синхронізуються на фізичну клітку і змінить її тип зіткнення від статичної до кінематики. Для створення платформи TileMap на основі рухомої платформи.

\ **Примітка:** Включення :ref:`collision_animatable<class_TileMap_property_collision_animatable>` може мати невеликий удар продуктивності, тільки це зробити, якщо TileMap переміщається і має з'єднання плитки.

.. _class_TileMap_property_rendering_quadrant_size:

.. rst-class:: classref-property

:ref:`int<class_int>` **rendering_quadrant_size** = ``16`` :ref:`🔗<class_TileMap_property_rendering_quadrant_size>`

.. rst-class:: classref-property-setget

- |void| **set_rendering_quadrant_size**\ (\ value\: :ref:`int<class_int>`\ )
- :ref:`int<class_int>` **get_rendering_quadrant_size**\ (\ )

Розмір квадросу TileMap. Квадрорант – група плиток, яка складається з одного полотна, для цілей оптимізації. :ref:`rendering_quadrant_size<class_TileMap_property_rendering_quadrant_size>` визначає довжину квадратної сторони, в координаційній системі мапи, що утворює квадрофон. Таким чином, за замовчуванням група квадранта розміром разом ``16 * 16 = 256`` плитка.

Розмір квадросу не наноситься на Y-сортовані шари, так як плитка згрупована позицією Y замість цього випадку.

\ **Примітка:** Квадроанти створюються відповідно до координаційної системи карти, квадрорантської "швидкої форми" не може виглядати як квадрат у локальній координатній системі TileMap.

.. _class_TileMap_method_set_cell:

.. rst-class:: classref-method

|void| **set_cell**\ (\ layer\: :ref:`int<class_int>`, coords\: :ref:`Vector2i<class_Vector2i>`, source_id\: :ref:`int<class_int>` = -1, atlas_coords\: :ref:`Vector2i<class_Vector2i>` = Vector2i(-1, -1), alternative_tile\: :ref:`int<class_int>` = 0\ ) :ref:`🔗<class_TileMap_method_set_cell>`

Встановлює ідентифікатори плиток для комірки на шарі ``layer`` з координатами ``coords``. Кожна плитка :ref:`TileSet<class_TileSet>` ідентифікується за допомогою трьох частин:

- Ідентифікатор джерела ``source_id`` визначає ідентифікатор :ref:`TileSetSource<class_TileSetSource>`. Див. :ref:`TileSet.set_source_id()<class_TileSet_method_set_source_id>`,

- Ідентифікатор координат атласу ``atlas_coords`` визначає координати плитки в атласі (якщо джерело є :ref:`TileSetAtlasSource<class_TileSetAtlasSource>`). Для :ref:`TileSetScenesCollectionSource<class_TileSetScenesCollectionSource>` це завжди має бути ``Vector2i(0, 0)``),

- Ідентифікатор альтернативної плитки ``alternative_tile`` визначає альтернативу плитки в атласі (якщо джерело є :ref:`TileSetAtlasSource<class_TileSetAtlasSource>`) та сцену для :ref:`TileSetScenesCollectionSource<class_TileSetScenesCollectionSource>`.

 Якщо ``source_id`` встановлено на ``-1``, ``atlas_coords`` на ``Vector2i(-1, -1)`` або ``alternative_tile`` на ``-1``, комірка буде стерта. Стерта комірка автоматично отримує **всі** її ідентифікатори, що відповідають їхнім недійсним значенням, а саме ``-1``, ``Vector2i(-1, -1)`` та ``-1``.

Якщо ``layer`` має від'ємне значення, доступ до шарів здійснюється з останнього.

|void| **set_cells_terrain_connect**\ (\ layer\: :ref:`int<class_int>`, cells\: :ref:`Array<class_Array>`\[:ref:`Vector2i<class_Vector2i>`\], terrain_set\: :ref:`int<class_int>`, terrain\: :ref:`int<class_int>`, ignore_empty_terrains\: :ref:`bool<class_bool>` = true\ ) :ref:`🔗<class_TileMap_method_set_cells_terrain_connect>`

Оновіть усі комірки в масиві координат ``cells``, щоб вони використовували заданий ``terrain`` для заданого ``terrain_set``. Якщо оновлена комірка має такий самий рельєф місцевості, як і одна з її сусідніх комірок, ця функція намагається об'єднати ці дві. Якщо ``ignore_empty_terrains`` має значення ``true``, порожні ландшафти будуть ігноруватися під час спроби знайти найкраще підходящу плитку для заданих обмежень ландшафту.

Якщо ``layer`` від'ємне, доступ до шарів здійснюється, починаючи з останнього.

\ **Примітка:** Для коректної роботи цей метод вимагає, щоб TileSet TileMap мав налаштовані ландшафти з усіма необхідними комбінаціями ландшафту. В іншому випадку це може призвести до неочікуваних результатів.
